# Текстовый API Ричи

> История U139. При локальной очистке 30 октября 2026 неактивная операторская
> копия `text-api.json` перенесена в закрытый внешний архив. Рабочие настройки
> PC не менялись; описание ниже не является текущей настройкой checkout.

**U139 закрыт частично: действующий клиент уже использует локальную модель PC. Новый клиент со сменяемыми учётными данными не установлен.** Подготовленный `text-api.json` сейчас не влияет на работающего Ричи. Прежний worker и слушание восстановлены; качество модели и разговорное поведение этой задачей не менялись.

## Действующая конфигурация

Файл на PC: `C:\Users\User\Desktop\reachy-companion\config.worker.local.json`.

- `network.llm_base_url`: `http://host.docker.internal:1234/v1` внутри Docker. С других компьютеров тот же сервер доступен по `http://192.168.2.134:1234/v1`.
- `llm.model`: `qwen3.5-9b-uncensored-hauhaucs-aggressive`.
- Действующий протокол: raw completion. Текущая локальная ветка не отправляет `Authorization`.

В работающем `/config` нет нового `text-api.json` и его helper. Горячее применение подготовленных настроек не работает; нельзя считать, что правка этого файла изменит следующий ответ.

## Подготовленная схема после установки нового клиента

Планируемый отдельный файл на PC: `C:\Users\User\Desktop\reachy-companion\text-api.json`, видимый worker как `/config/text-api.json`. **Этот путь пока не является источником настроек действующего worker.** Сначала нужны успешная установка клиента и квалифицированный reload worker. Предусмотренное в подготовленном коде чтение перед каждым обычным ответом не принято как работающая runtime-возможность.

Подготовленные поля:

- `base_url`: адрес API до `/v1` включительно, без учётных данных в URL.
- `model`: точное имя модели.
- `protocol` и `api_path`: для нынешнего сервера `completion` и `/completions`; для совместимого chat API — `chat_completions` и `/chat/completions`.
- Учётные данные: только один из `api_key`, `api_key_file` (относительный путь в каталоге конфигурации), `api_key_env` (имя переменной окружения worker). Все пустые — без авторизации.

Переменная окружения контейнера требует отдельного применения окружения. Будущее чтение ключа из файла/конфига при следующем ответе относится к подготовленному клиенту, который ещё не установлен. Ключи в чат не нужны.

`text-api.json` в этом репозитории — неактивная подготовленная операторская копия с LAN-адресом PC. Автоматической синхронизации с рабочим PC нет. Заменить в ней адрес и ключ сейчас недостаточно для подключения внешнего провайдера.

Нативная проверка эквивалентности прежнего и подготовленного payload выполнена без запросов к модели. Применение нового клиента остановлено на обслуживающем guard до замены исходника; причина его `RuntimeError` не сохранена. Повторная установка, реальный внешний API и новые учётные данные не проверялись. Запуск/остановка модели и её ресурсы не менялись.

«Общий реестр» в прежнем обсуждении означал блокировку и учёт конкурирующих операций запуска/остановки. Наличие такого действующего canonical-механизма на PC не подтверждено. Для указания URL текстового API он не нужен, а пустой указатель в конфиге не доказывает неисправность автозапуска.
