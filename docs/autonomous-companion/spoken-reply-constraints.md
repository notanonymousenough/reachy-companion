# Request-scoped spoken reply constraints

The legacy LM Studio raw `/v1/completions` request and ordinary stream acknowledgements remain the defaults. An authenticated `/text` or `/turn` request may explicitly supply:

```json
{"reply_constraints":{"schema_version":"reply-1","max_chars":60,"no_question":true,"no_wake":true}}
```

This path uses the configured model and messages through `/v1/chat/completions`, with a strict reply-only JSON schema. It never substitutes a preset, truncates text, strips reasoning/tags, retries as free text, or emits an acknowledgement. Empty input, pause/reset/stop and `/say` reject constrained requests before their control effects. Only complete `finish_reason=stop`, strict JSON with exactly one `reply` key, valid spoken text and unchanged expression processing can reach TTS. History receives plain spoken text after successful synthesis as before.

The schema bounds length and punctuation. Host validation independently checks length, forbidden markup, a word character, normalized question marks, and wake substrings. Normalization uses casefold/NFKD/removal of combining marks and the fixture's Latin-to-Cyrillic mapping for mixed wake names. This detects punctuation and selected wake spellings; it does not establish that a sentence cannot implicitly ask a question. The independent fixture's question/wake, source age, operator epoch, global deadline, PCM duration and actual consumed playback guards remain mandatory. A character bound does not guarantee a TTS duration or latency.

## Capability gate

[LM Studio documents JSON schema output on chat completions](https://lmstudio.ai/docs/developer/openai-compat/structured-output). This does not prove that the currently loaded model/runtime implements each schema keyword. Before enabling this path, the sole hardware runner must complete the bounded PC-only capability probe on the already loaded model, without model reload or production configuration changes. Record model/runtime identity, endpoint, exact schema hash, finish reason, validity and latency as aggregate evidence. An accepted HTTP request alone cannot demonstrate enforcement of `maxLength` and `pattern`; inspect the generated result and capability evidence, and keep host validation regardless.

Absent a verified operator profile, a constrained request fails before inference. An isolated trial configuration may set `llm.reply_schema` as follows, replacing placeholders with the exact audited current values:

```json
{"enabled":true,"verified":true,"model":"EXACT_CURRENT_MODEL","base_url":"EXACT_CONFIGURED_BASE_URL","api_path":"/chat/completions","max_length_verified":true,"pattern_verified":true}
```

`api_path` is appended to the configured base URL and must resolve to exactly `/v1/chat/completions`; a base URL ending in `/v1` uses `/chat/completions`. The profile must match the configured model and base URL. This profile records operator evidence; it is not cryptographic attestation. A changed loaded model/runtime invalidates the evidence and requires a new capability check. No production defaults or model settings are changed by this feature. Unsupported schemas, backend errors, malformed output and guard failures fail closed.

## Optional fixed-instance raw SDK route

The PC-only raw SDK probe on 2026-10-15 produced a complete, valid reply on the already loaded model using Python SDK 1.5.0 and the existing raw prompt template/prefix. This establishes the observed raw generation format for that probe. It does not validate the HTTP chat route or atomic instance selection: public `.complete()` in this SDK passes a symbolic identifier query. The separate fixed-reference route below still requires its own actual PC capability check before enabling.

[Text completion](https://lmstudio.ai/docs/python/llm-prediction/completion) supports raw prompts and [prediction parameters](https://lmstudio.ai/docs/python/llm-prediction/parameters) support structured inference configuration. Our optional mode `sdk_raw_instance_v1` deliberately uses an audited private SDK core to avoid symbolic identifier reuse. It calls public `client.llm.get_model_info` with `{type: instanceReference, instanceReference: trustedRef}`, checks the model identifier/key, exact reference and context, then passes the same fixed reference to `_complete_stream` and waits for the actual terminal result. It never invokes model discovery, `.model()`, `getOrLoad`, load or unload. There is no symbolic selector, HTTP chat or free-text fallback. A missing instance rejects before prediction; an instance disappearing during the RPC must fail rather than target a new instance with the same identifier.

The implementation pins SDK 1.5.0, its critical API/model/serializer files, and the complete 25-file Python source tree. It checks installed distribution versions through an operator-audited whole-environment digest before importing SDK. No dependency is installed automatically. Profile fields below belong only in the isolated audited trial config; absent or mismatched evidence rejects the request:

- `mode: sdk_raw_instance_v1`, `enabled: true`, `verified: true`, `instance_spec_verified: true` only after the exact fixed-reference capability probe passes.
- Exact configured `model` and `base_url`, actual `model_key`, `instance_reference`, `context_tokens`, and the audited `runtime_build` record. The base URL must be HTTP without userinfo/query/fragment, with only an empty, `/` or `/v1` path; the SDK receives its exact host/port.
- `sdk_version: 1.5.0`, `sdk_sources: SDK_SOURCES`, `sdk_tree_sha256: SDK_TREE` from the published adapter; `environment_sha256` from its read-only `environment_audit()` on the actual isolated image.
- `template_sha256: template_binding(config)` binds the current message template, assistant prefix, stop strings, temperature and configured token cap. The raw prompt construction remains the legacy construction, including its existing control-marker cleanup of input messages. The generated output is never cleaned or rewritten.
- `constraints_sha256: digest(exact_request_constraints)` and `schema_sha256: digest(response_format(exact_request_constraints)['json_schema']['schema'])` bind the exact tested request/schema. A changed schema requires new evidence; a successful different schema is insufficient.
- `max_tokens` must be an integer within both 512 and the configured cap; `timeout_s` must be finite, positive, at most 120 seconds and at most the configured LLM timeout. The optional route sends only known typed `maxTokens`, `temperature`, `stopStrings` and `structured: {type: json, jsonSchema: schema}`. It adds no thinking flags or presets.

A normally returned prediction is terminal evidence, after which only `eosFound` or `stopStringFound`, a matching model key and strict validated final `result.content` can succeed. `parsed`, reasoning fields, partial text, token-limit output and tag stripping are never used as substitutes. SDK-side parsing failures conservatively count as unknown if no terminal result returned to the adapter.

The process owns one SDK operation slot. A caller timeout discards any late answer and leaves the slot occupied until the real worker returns. Only an actual SDK terminal return allows reuse. A transport/SDK failure after submission permanently quarantines this process's slot: worker exit, `future.cancel`, a sent cancel request, connection close or elapsed time do not prove backend cancellation. Subsequent SDK calls and legacy brain calls to the same configured LM Studio base URL/model reject while the SDK operation is active or quarantined. Other configured backends keep their usual behavior. The existing single Pipeline lock prevents ordinary worker turns from overlapping; this is an additional guard for abandoned SDK work, not a distributed lock across independent processes. There is no automatic reset/reclaim API. Owned service recovery must independently establish old backend completion before restarting into a new generation; a process restart alone is not backend cancellation evidence. Active/unknown status is available from `SLOT.status()` and contains no prompt or answer. Existing external TTL, epoch, wake, PCM duration and consumed-playback guards remain required.
