# Local lease guard: подготовка этапа3

`autonomous/actuator_guard.py` — отдельный opt-in компонент, не подключённый к production speech/motion. Он не содержит robot SDK, motor enable, TTS, capture или LLM вызовов. `arm` доступен только trusted owner; переданные operator flags/fence attestation пока являются входом этого владельца, а не самостоятельно доказанным hardware state. Поэтому наличие класса не снимает physical activation gates.

Реализованы process-lifetime `flock` для cooperating writers, новый robot-local boot ID, неизменяемая lease с полным Authority, monotonic deadline≤500ms, fresh heartbeat sequence и независимый watchdog с poll≤100ms. Старую lease нельзя продлить после expiry, смены boot или revoke. Watchdog вызывает adapter stop без обращения к hub/PC/model; stop обязан подтвердить фактическое прекращение output. False/exception означает unknown и запрещает новую lease. Operator invalidation будущего adapter обязана немедленно вызвать revoke, до очередного model tick.

SQLite `synchronous=FULL` хранит active/idle/quarantined intent. После crash активного владельца следующий процесс получает quarantine; completion старого процесса не возобновляется. Отдельный trusted `acknowledge_stopped(verified_stopped=True)` — будущий operator audit, не model tool и не автоматический reset. Admission command intent записывается до future dispatch; duplicate возвращает False. Таблица ограничена256durable command IDs: overflow отзывает lease, не выбрасывает tombstones ради повторного исполнения. Tombstones переживают новые lease и restart: re-arm с новой authority не разрешает replay того же command ID. Безопасный lifecycle/GC этих записей пока не реализован; при заполнении компонент withdraw, не очищается автоматически.

Stop вызывается перед дополнительной SQLite записью: storage error не может пропустить stop и оставляет RAM quarantine; old durable active row сохраняет quarantine после restart. Это не hard real-time доказательство: fsync или blocking adapter callback под общей mutex могут задержать watchdog. Физический adapter должен иметь отдельный bounded enqueue/stop и независимый output watchdog; пока такого adapter нет. `admit` отдельно от dispatch не разрешает TOCTOU: future adapter должен удержать guard mutex до своего bounded enqueue. Проверка боевого operator state, authenticated leases и sole-owner fence всех native/SDK writers ещё не интегрированы.

## Durable operator epochs и isolated Agent restart

`MicrophoneState` теперь сохраняет enabled+monotonic epoch через unique0600 temporary file, file fsync, atomic replace и directory fsync. Legacy enabled-only file совместим с epoch0. Corrupt/noninteger/negative/exhausted epoch failclosed. Save failure выключает current process, отзывает listening/pending/resume/playback и сообщает error; **не обещает** сохранение mute после failed write. Boot UUID нового Agent и persisted microphone epoch публикуются через тот же `Agent.status()`/HTTP `/status`; это process identity, не robot kernel boot или sole-writer proof. Status берёт operator lock, чтобы не выдавать частичный успешный switch. Пара boot+epoch должна проверяться будущим actor handshake; интеграция всех native writers ещё не выполнена.

Muted manual/voice/play отклоняются до compute/audio dispatch. Mute, завершение старого ответа и paused muted loop снимают очередь expressions вместо постановки нового neutral motion. Уже исполняющийся hub/native motion этим не подтверждён как stopped: нужен отдельный guarded adapter/verified stop. Production службы не переключались.
