# Local lease guard: подготовка этапа3

`autonomous/actuator_guard.py` — отдельный opt-in компонент, не подключённый к production speech/motion. Он не содержит robot SDK, motor enable, TTS, capture или LLM вызовов. `arm` доступен только trusted owner; переданные operator flags/fence attestation пока являются входом этого владельца, а не самостоятельно доказанным hardware state. Поэтому наличие класса не снимает physical activation gates.

Реализованы process-lifetime `flock` для cooperating writers, новый robot-local boot ID, неизменяемая lease с полным Authority, monotonic deadline≤500ms, fresh heartbeat sequence и независимый watchdog с poll≤100ms. Старую lease нельзя продлить после expiry, смены boot или revoke. Watchdog вызывает adapter stop без обращения к hub/PC/model; stop обязан подтвердить фактическое прекращение output. False/exception означает unknown и запрещает новую lease. Operator invalidation будущего adapter обязана немедленно вызвать revoke, до очередного model tick.

SQLite `synchronous=FULL` хранит active/idle/quarantined intent. После crash активного владельца следующий процесс получает quarantine; completion старого процесса не возобновляется. Отдельный trusted `acknowledge_stopped(verified_stopped=True)` — будущий operator audit, не model tool и не автоматический reset. Admission command intent записывается до future dispatch; duplicate возвращает False. Таблица ограничена256durable command IDs: overflow отзывает lease, не выбрасывает tombstones ради повторного исполнения. Tombstones переживают новые lease и restart: re-arm с новой authority не разрешает replay того же command ID. Безопасный lifecycle/GC этих записей пока не реализован; при заполнении компонент withdraw, не очищается автоматически.

Stop вызывается перед дополнительной SQLite записью: storage error не может пропустить stop и оставляет RAM quarantine; old durable active row сохраняет quarantine после restart. Первоначальный prototype использовал общую mutex для fsync/stop; ниже описан отдельный output watchdog и `dispatch`, снимающие disk contention. Это не hard real-time доказательство: blocking adapter callback/OS latency остаются непроверенными. Physical adapter должен иметь bounded enqueue/verified stop и пройти all-writer fence. Legacy `admit` только записывает intent; future physical adapter обязан использовать `dispatch`, а не держать SQLite mutex вокруг SDK writes. Проверка authenticated leases и sole-owner fence всех native/SDK writers ещё не интегрированы.

## Output watchdog вне storage mutex

Новый RAM `OutputGate` зеркалирует live lease/deadline отдельной mutex и watchdog thread, который никогда не берёт SQLite/ActuatorGuard mutex. Durable active intent по-прежнему записывается до arm return. Heartbeat не возрождает expired output lease. Output revoke вызывает stop один раз на lease и сохраняет known/unknown completion; persistent guard затем фиксирует idle/quarantine. Disk failure не становится known stop.

`dispatch(lease,command_id,enqueue)` записывает durable dedupe intent, повторно проверяет lease после fsync и выполняет bounded enqueue под output gate. Revoke между intent и enqueue отвергает команду; delayed intent не попадает в output после expiry. Duplicate command не вызывает enqueue повторно, tombstones сохраняются. Adapter enqueue/stop **не имеют права** выполнять storage/model work или вызывать ActuatorGuard APIs; bounded callbacks — ещё обязательство будущего native adapter, не измеренная hardware гарантия. Долгий callback может задержать output watchdog, поэтому physical acceptance ещё закрыта. Legacy `admit` сам по себе не разрешает native I/O.

Второй test отзывает lease точно между durable intent и enqueue; stale/duplicate output не возникает. Остальные crash/quarantine/unknown/dedupe tests сохранены.

## Consumed PCM readiness и unverified resume

File-only robot audit: configured playback `plug:reachymini_audio_sink`, existing `.asoundrc` sinktype `dmix`, slave16kHz/stereo, libasound present. Три hardware playback stream status без owner PID; они не дают per-Agent cursor. PCM handles/audio initialization не открывались. Actual Agent micfalse/capturefalse/phasepaused, daemon lockfree/motorsdisabled/movesempty; это не исключает direct SDK writers. Process hints теперь экспортируют только fixed known roles, без scripts/argv/env; inventory исключает собственный PID.

Текущий `SpeechClock` — wall-time estimate после записанных в aplay pipe bytes. Его `resume_cursor()` всегда unknown (`None`), независимо от длительности playback. Interrupted streaming сохраняет captured user phrase, но discard pending replay при unknown cursor и сообщает `resume_blocked_reason=unverified_pcm_cursor`; прямой unverified replay отвергается до compute/network/audio. Empty-input auto-resume тоже требует trusted internal `cursor_verified=True`; текущий aplay adapter не создаёт такой saved reply. Unit fixture с verified flag проверяет только replay reducer, не hardware consumption. Existing cue clock пока остаётся estimate, не accepted physical synchronization.

[ALSA PCM reference](https://www.alsa-project.org/alsa-doc/alsa-lib/pcm.html) определяет delay/available frames для **собственного** PCM handle; `snd_pcm_avail_delay` синхронизирует обе метрики. [Pause capability](https://www.alsa-project.org/alsa-doc/alsa-lib/group___p_c_m___h_w___params.html) проверяется на configured handle. Shared dmix/slave stereo и plugin conversion требуют отдельного native adapter audit; backend progress не доказывает acoustic consumption/sole writer. Новый adapter пока не открыт и не подключён: сначала local writer fence, текущие epochs, bounded enqueue/drop/stop, actual delay/state/underrun observations и uncertainty. Неизвестный status/restart/xrun должен отзывать resume, а не extrapolate по wall time.
