# Конечный native actor и первое распознавание изображения

2026-10-10. Это ограниченные hardware/PC эксперименты. Production `guarded_motion.enabled` остаётся false; Agent endpoint связан с reusable native IPC runtime и проверен в конечной managed systemd-сессии; непрерывный production owner ещё не развёрнут. Speech/ALSA consumed cursor и production semantic-camera admission не приняты.

## Единственный writer и восстановление

`native_actor_probe.py` сначала проверяет actual operator boot/epoch, mic=false/capture=false/paused, factory ready/disabled/no running moves, private-config hash и все доступные root `/proc/*/fd` для motor UART. Исходный единственный serial owner должен принадлежать factory cgroup. Bluetooth helper и GPIO shutdown process проверены отдельно: serial handles у них отсутствуют; их службы не останавливаются.

Изолированный import проверяется от pollen и в actual transient systemd unit до изменений служб. Root supervisor создаёт UUID owner marker и независимый 30s rollback timer, затем runtime systemd condition, запрещающий factory restart на время владения. После остановки всего factory cgroup port должен стать owner-free; попытка factory start обязана дать ConditionResult=no и не открыть UART. Child имеет отдельный RuntimeMaxSec=12s. Внутри него используется pinned synchronous Rust controller, без queued PyControlLoop, а свежие protocol2 register reads используют тот же fd. Kernel TIOCEXCL и отказ второго ordinary open с EBUSY проверены на роботе. Это не запрет привилегированному администратору снимать fence и не отзыв уже открытых чужих fd; поэтому root audit/withdrawal предшествует native constructor.

Один RAM trajectory worker владеет всеми target/read/enable/release операциями. Guard callbacks не стоят в старой SDK queue. Motion lease независим от mic permission, TTL150ms/poll5ms; worker имеет собственный monotonic deadline и не допускает revival после expiry/withdraw. Один motor17, offset≤2°, ramp400ms, finite duration≤2s; head/body и другая антенна не включаются. Измеренная начальная поза должна быть stationary. Stop отменяет собственную траекторию, пишет current antenna pose один раз и требует ≥200ms fresh feedback: range всех девяти axes≤1.1 encoder ticks, endpoint velocity≤0.02rad/s, без дальнейших trajectory updates. Stop callback ждёт≤300ms; неизвестный I/O/settling даёт false/quarantine. Это practical measured hold, не доказанный hard realtime bound и не all-torque-off substitute.

До любого torque-on fsync сохраняет recovery intent с исходными девятью torque=0 и единственным разрешённым ID17. Rollback сначала останавливает свой child и factory, затем отдельным synchronous controller отключает только разрешённый motor и читает torque всех девяти. Лишь после verified release снимается runtime condition и запускается factory. Без intent native recovery вообще не импортируется: hardware не было допущено. Неизвестный release оставляет factory fenced. Owner UUID/flock исключают rollback старого timer поверх нового владельца. Production ready/disabled/no moves, operator equality и config equality входят в итоговую приёмку.

Первый запуск обнаружил ошибку resolution старого flat shadow package; recovery import также упал и временно оставил factory inactive. Вручную восстановленная служба была проверена ready/disabled/no moves. Torque-on до этого не выполнялся. Исправления: explicit source-root insertion, настоящий systemd import preflight, recovery import по точному файлу и no-intent recovery без доступа к hardware. Последующие finite transitions восстановили factory и сохранили Agent boot/epoch/mute/private config.

Antenna17 limits3.5–7.0V, shutdown52, position mode3, Pgain200, PWM limit885/current limit1750, position limits0..4095, drive/homing0. Нулевое движение не объясняется неправильным ID или пустыми gains/limits.

Robot input envelope сам по себе не доказывает допустимость motor rail. [ROBOTIS XL330 specification](https://emanual.robotis.com/docs/en/dxl/x/xl330-m077/) и [Reachy voltage-fault report](https://github.com/pollen-robotics/reachy_mini/issues/589) показывают, почему alert нельзя считать общей нормой. Однако установленный [Reachy SDK1.11.0 backend](https://github.com/pollen-robotics/reachy_mini/blob/v1.11.0/src/reachy_mini/daemon/backend/robot/backend.py) явно фильтрует только Input Voltage Error при voltage≤7.8V, а [native1.5.6](https://github.com/pollen-robotics/reachy-mini-motor-controller/blob/v1.5.6/src/controller.rs) исключает status1 из reboot decision. Поэтому finite wireless fixture допускает только exact installed backend SHA256 `16d3dae8add1f30eb608de8aa9ae04d1afd31924fc7d5729bf515823f4bcdd57`, native binary SHA256 `799457a35b52171ae53ef5504c3c9b014ca699384ef1c767aa6af5e2194b7983`, exact models/limits/shutdown52, voltage6.8–7.6V, temperature<45°C и health0/1. Иные profiles/errors/voltage/temperature запрещены. EEPROM, voltage limit, shutdown, gains и firmware не меняются; alert остаётся видимым в receipts. Это воспроизведение ограниченного factory profile, не сертификация generic XL330 overvoltage.

Это **finite native movement + heartbeat-expiry measured-hold acceptance**; остаточный following error около14ticks/1.23° показывает, почему target2° не объявляется точным actual2° и почему постоянная expressive-motion policy пока не принята.

## Интегрированный native runtime: второй конечный этап

Реализованы `MotionProxy`, `MotionRuntime` и bounded Unix `RuntimeServer`, а не очередной standalone motor probe. Production Agent handler `/actors/motion/native` использует тот же proxy, что finite HTTP adapter; Hub имеет explicit `native_motion`. Production flag по умолчанию false и не менялся на устройствах. Существующие production Agent/Hub службы не обновлялись этим экспериментом: actual Hub client использует изолированный пакет и finite endpoint. На роботе runtime действительно запускается от pollen как managed transient systemd service под описанным root fence, при остановленном factory cgroup. Это приёмка reusable маршрута в конечной сессии, не приёмка непрерывного production lifecycle.

Agent проверяет actual Agent boot/operator epoch и передаёт envelope без перепривязки. `/operator` предоставляет независимый authenticated operator receipt, чтобы service monitor не рекурсировал через собственный `/status`/IPC; finite adapter с прежним flag-off Agent использует старый `/status`. Socket mode0600/owner UID и Linux SO_PEERCRED проверены; PID в каждом reply должен совпадать с kernel peer. Ready требует actual root ownership attestation, kernel exclusivity, известных operator/policy и отсутствия quarantine. Socket loss/неизвестный reply не дают REST fallback.

Единственный поддержанный path `/native/antenna` имеет typed `arm`, `trajectory`, `heartbeat`, `revoke` с exact keys, Agent/actor boot IDs, operator epoch, Hub boot/command ID и acquired lease. Ограничения trajectory: antenna17, offset≤2°, duration0.4–2s, ramp400ms, absolute position range без wrap. Exact fresh static drive/homing/PWM/current/position/gain/profile registers теперь входят в admission gate; register changes запрещены. Head/body/legacy REST envelopes отвергаются. Motor grant независим от mic permission: mic=false не разрешает мотор сам по себе. Runtime требует отдельную authoritative policy callback; default без callback запрещает движение. Quiet/privacy/motor withdrawal независимо вызывает stop и делает этот owner unready без revival при обратном переключении. Finite root adapter выдаёт только antenna grant с quiet=false; privacy-all берётся из локальной policy. Постоянный operator motor/quiet policy adapter ещё требует отдельной production приёмки.

IPC не выполняет serial I/O: trajectory dispatch только ставит bounded RAM job sole-writer worker. Native runtime TTL250ms/poll5ms, heartbeat sequence monotonic; worker независимо проверяет monotonic deadline/withdrawal. Durable command IDs для arm/trajectory/heartbeat/revoke не удаляются, не перепривязываются и не переисполняются после рестарта. Capacity256 fail closed, retired Hub bindings bounded128. Active/stopping crash row по умолчанию даёт quarantine. Trusted recovery acknowledgement не доступен HTTP/model: root-selected audit сначала проверяет sole ownership, все torque0 и stationary baseline, затем снимает quarantine без lease/command restoration. Неизвестный physical hold сохраняет quarantine; новый arm требует release предыдущего verified hold и fresh preparation.

Первый end-to-end запуск не принят: HTTP readiness появился до прогрева camera relay, lease150ms истёк до первого heartbeat и actual displacement был0. Исправлено: relay PLAYING предшествует HTTP readiness, native-runtime lease250ms. Это не изменение generic speech guard или исторического150ms fixture.

Actual повтор `native-endpoint-hub-live2.json`: Hub→finite Agent adapter→Unix peer→native worker дал **9encoder ticks/0.791° measured displacement** при target≤2°, 34target writes. После прекращения heartbeat verified hold получен за **485.714ms**, hold window225.471ms/9samples/range1tick/endpoint velocity0.00722rad/s, trajectory updates after hold0. Девять heartbeats приняты с IPC latency14–23ms; arm272ms включает pre-lease preparation. Duplicate trajectory ID и heartbeat revival отвергнуты. Второй fresh lease проверил explicit revoke: hold verified за244.914ms, request275.3ms; у второго движения measured displacement0, поэтому второй физический movement не заявляется. Root receipt `native-endpoint-runtime-live2.json` подтверждает kernel sole writer, verified release всех torque0, factory ready/disabled/no moves и неизменные operator/private config. Один stop486ms не доказывает P95 или hard realtime bound.

Actual SIGKILL failure injection `native-endpoint-owner-failure-live.json` уничтожил только owned native unit после **7ticks/0.615° measured movement**. Hub receipt `native-endpoint-owner-failure-hub-live.json` зафиксировал owner failure без retry/fallback. Independent root rollback сначала исключил умершего writer, выполнил release antenna17, прочитал all9 torque0 и восстановил factory. Parent accepted=false/CalledProcessError здесь ожидаем: child действительно аварийно завершился; успешный recovery не выдаётся за успешную trajectory.

Actual restart `native-endpoint-restart-quarantine-live.json` создал новый boot/PID/kernel sole owner, но ready=false/quarantined=true. Hub `native-endpoint-replay-quarantine-live.json` отверг старую trajectory и rebound с новым actor boot при прежнем consumed command ID; writes0/leased=false. После explicit root audit `native-endpoint-restart-audit-live.json` новый owner имел ready=true/quarantined=false. `native-endpoint-replay-audit-live.json` снова отверг оба replay: stale boot, затем persistent consumed ID; writes0/leased=false/binding=null. Оба restart parent/child accepted=false, поскольку movement acceptance требует actual actor/verified hold, а эти тесты намеренно не создавали actor. Их отдельные replay receipts accepted=true; no-intent recovery не обращался к hardware, factory/operator/config восстановлены. Это проверка восстановления готовности и сохранения ledger, а не новое моторное движение.

## Камера при withdrawn factory

`CameraRelay` использует installed libcamerasrc→bounded/leaky queue→5fps unixfdsink с factory camera IPC path и launcher-declared GStreamer/libcamera environment. Это camera-only relay: без audio/WebRTC/ML/file sinks. Неизвестный существующий socket owner запрещает takeover; shutdown требует NULL и удаления собственного socket. Video Producer после трёх missing samples очищает latest и пересоздаёт старый Unix reader, сохраняя свою lineage/policy.

Actual `camera-native-coexist-live2.json` принят: один Producer получил frames **до factory withdrawal, во время native ownership и после factory restoration**, одна lineage. За50s producer receipt содержит **45frames, 31gaps**, continuity client69transient poll errors. Capture thread reaped; raw frame files0, private frames exported0, semantic inference requests0, audio/motor commands0, operator unchanged. Это восстановление camera coexistence с наблюдавшимися разрывами, не gapless video или latency P95. Первое короткое окно не захватило post-factory frames и не было принято. Existing factory имеет собственный media/audio lifecycle; camera-only relay не является доказательством отсутствия всех системных PCM handles.

Финальная recovery-only сессия `native-endpoint-restart-audit-final.json` дополнительно прошла camera shutdown NULL verification и native cleanup: ready=true, writes0, factory/operator/config restored. Параллельный Hub client с прежним10s startup budget не застал endpoint readiness; этот повтор replay не принят. Startup budget клиента исправлен на30s для root preflight/withdrawal/camera warmup, с сохранением timeout receipt; robot unit/lease limits не увеличивались. Предыдущий actual replay-audit acceptance сохраняет отдельный receipt выше.

Private camera semantic inference по-прежнему запрещён до retention admission для prepare_image/upload, effective image/context/VRAM budget и TTL/lineage acceptance. Synthetic9B result выше не меняет этот gate; новые private uploads, model loads и audio commands на этом этапе отсутствуют.

164 local regression tests прошли, включая actual Unix proxy/peer receipts, expiry/dedupe/no revival, stale boot/epoch, authoritative policy withdrawal, crash quarantine/explicit recovery ledger, absolute position wrap rejection и unknown camera shutdown без удаления socket. Production flag остаётся off; continuous ownership, quiet/motor operator wiring, precise tracking/head/body, semantic-camera admission и speech consumed cursor остаются следующими отдельными этапами.
