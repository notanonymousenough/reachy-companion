# HTTP prediction ownership after transport failure

A local loopback reproduction against source baseline `87d239d` used the real `Pipeline.turn`, an HTTP fake model server, and synthetic text only. The first request timed out while the server deliberately kept that operation alive. The Pipeline released its local lock; a second turn succeeded and its second POST arrived before the first server operation was released. This proves a client-side same-backend admission gap after transport failure. It does not claim that a real LM Studio model was tested or cancelled.

The fix adds a synchronous process-local ownership registry in `brains.py`. It reserves the exact configured LM Studio base URL/model before HTTP open; the optional SDK core reserves the same identity before any SDK client operation. Existing ordinary payload bytes, prompts, model parameters, endpoints, voice and production configuration remain unchanged. OpenClaw/Hermes are outside this LM Studio guard. There is no extra daemon, inference thread, SDK installation or dependency for the HTTP path.

## Terminal evidence and unknown state

The HTTP operation reads one complete response envelope, bounded to 1 MiB, using strict JSON decoding that rejects duplicate keys and non-finite values. Terminal evidence requires exact equality between response `model` and the configured model ID, exactly one choice at index zero (zero is the default if index is omitted), and `finish_reason` equal to `stop` or `length`. This is a response on the owned request connection, not an unrelated status poll. A `length` terminal result frees operation ownership but still fails speech acceptance; invalid speech after a matching terminal result likewise does not poison the backend. No truncated output is repaired, retried or used as speech.

Before deployment, independently verify the actual current LM Studio response model string equals the configured model ID. A symbolic alias is not automatically the response ID. Missing, mismatched or ambiguous model identity correctly leaves the operation unknown; do not invent an allowlist to make a deployment pass. Use existing actual response metadata if available. Any additional real PC-only probe belongs to the sole runner and must wait until the current live turn and its cleanup are terminal.

Timeout, disconnect, invalid/truncated/oversized JSON, unknown finish reason or mismatched identity after an HTTP attempt leave a sticky `unknown` registry entry. New requests to that same configured base URL/model reject before HTTP open. A connection failure before actual submission may conservatively quarantine as well, since the client does not guess whether the remote side accepted work. Other configured identities remain independent. Pre-submission validation failure releases its unused entry. Healthy terminal completion releases its entry for the next fresh turn.

The registry stores at most sixteen active/unknown identities. It never evicts unknown entries to admit a new identity; capacity exhaustion fails closed. It has no reset, elapsed-time expiry, cancellation endpoint or automatic retry. `MODEL_EXECUTION.status(identity)` exposes only local active/unknown booleans. A server-side test fixture releasing work does not clear a client's unknown entry when the terminal response was never received. Service restart clears process memory but is not evidence that old backend inference ended; an owned recovery must independently establish old completion or verified backend cancellation before another inference is admitted in a new generation. This registry does not coordinate other independent clients/processes.

SDK interoperability reuses its existing actual-operation slot. A shared ownership reservation happens before creating the SDK client, so HTTP active/unknown blocks a direct SDK helper call as well. SDK active/unknown blocks the same HTTP helper even if its caller bypasses the higher-level `answer` check. The caller's timed-out SDK wait never releases ownership while the worker is still running. A normally returned SDK result must match the audited model key before releasing shared ownership; mismatched identity remains unknown. This does not enable the unverified optional SDK route or install SDK on the current worker.
