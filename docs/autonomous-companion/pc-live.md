## Воспроизводимость

`deploy/autonomous/pc_probe.py` запускает три transport/syntax samples. `deploy/autonomous/live_smoke.py` принимает пути server/fast GGUF/main GGUF/example config/output; выполняет пять semantic cases, exact counts и optional main completion. Только при5/5 проходит дальше в12s mixed real fast/main scheduler, где требуется one task/one fresh simulated commit. Каждый CPU process завершается и reaped в finally; output/log остаются локально. Main inference использует только loaded handle, никогда не вызывает load/unload. Paths, локальные manifests и raw reports не коммитятся. Tokenizer SHA здесь покрывает весь GGUF с embedded tokenizer; это provenance совместного артефакта, не отдельно извлечённый tokenizer digest.

Regression tests покрывают native grammar aliases/mute и truncated native completion/admission cap. Первый успешный hardware audit не снимает stage3 stop/ownership/watchdog gates.

## Полный FastView и текущая реплика

После task-only baseline включён full по умолчанию: никакая обязательная группа не исчезает ради скорости. Только opaque aliases заменяются на request-local короткие имена; timestamp расположен после стабильных полей для возможности runtime prefix reuse. Никакие решения модели не кешируются. Retained dialogue остаётся после start, в pending и ready, затем заменяется новой репликой. Operator transition очищает current dialogue и неисполненные candidates: новая binding после unmute не может заново запустить pre-mute input. Authority epochs и неизвестные execution permits сохранены.

## Compact native wire experiment (не выбранный latency профиль)

Opt-in fast `decision_format=tuple` только для `llama_native`; object остаётся default. Полный FastView и обязательная реплика сохраняются. Модель выдаёт `[action,reference,reason]`; host проверяет exact3 strings, available candidate/ready/focus groups, muted capability mask и reason≤96, затем переводит фактический reference в canonical FastChoice и исходный opaque alias. Candidate kind берётся из выбранного typed candidate, никакой отсутствующий task/capability не создаётся. EOS/word, exact tokenizer/admission и authority fences неизменны. Native completion теперь возвращает actual `tokens_predicted`, если endpoint действительно сообщил integer, без расчёта по символам.

Первый tuple schema с prefixItems/itemsfalse не дошёл до prediction: transport failure→execution unknown→fast quarantine; CPU finite supervisor reaped. После explicit Draft7 tuple items-array actual model passed5/5. [Upstream schema implementation](https://github.com/ggml-org/llama.cpp/blob/master/common/json-schema.cpp) выбирает items при наличии обоих полей; конкретный build проверялся отдельно, public master не считается доказательством его версии.

Actual CPU8/cache0/full: idle1.375/new1.188/pending1.500/ready1.422/muted1.469s,305–370input tokens,20–21actual output tokens. Main0.937s. Mixed12s/period1:6fresh requests/6accepted,6busy tick gaps,one main/ready/simulated commit, main1.047s; CPU reaped. Функциональный slice прошёл, cadence **не прошёл**; output formatting сократил input, но не доказал latency improvement. Поэтому tuple не включён в выбранный профиль и не выдаётся за1Hz.

Дополнительный probe с whitespace-free hand-written GBNF и one-word rationale снизил output до9–11tokens, но прошёл только4/5: в ready case модель выбрала rest вместо commit. Latencies1.063/1.187/1.094/1.375/1.063s; даже это не1Hz/P95≤700ms. Variant отвергнут, GBNF не оставлен в runtime; opt-in tuple использует проверенный Draft7 schema вариант. Existing main9B/context32K не перезагружались, hardware/audio/motor commands отсутствуют. 125tests проверяют tuple capability groups, unknown aliases/extra fields/mute, native finish gate и original alias mapping; это не доказательство quality вне пяти cases.
