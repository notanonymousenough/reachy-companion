## Поведение и небольшой diff

Два patch-файла: `deploy/patches/alice-short-replies-{voice,config}.py.patch`. Worker получает один validator, два небольших метода и вызовы в `prepare`, непосредственно перед unary/stream TTS и в acknowledgement gate. Config получает только типизированный `conversation.alice_short_replies=false`. Новых зависимостей нет. HEAD `src/reachy_companion/voice.py`/`config.py` не заменяются: применимы только generated bytes ниже.

Режим включается **совместно** флагом `conversation.alice_short_replies=true` и effective `speech_address_prefix="Алиса, "` (существующий config default или явное request override). При пустом prefix обычный пользовательский разговор сохраняется; при false сохраняется весь прежний Alice runtime. Включённый режим охватывает `/text`, `/turn` и `/say`, чтобы ручная озвучка тоже не обходила ограничение. STOP/пустая STT остаются беззвучными.

Перед TTS допускается ровно один непустой existing expression segment и ровно одно предложение с конечной `.`, `!` или `?`. Лимит **11 слов вместе с обращением**, 120 символов вместе с обращением; слово считается `[^\W_]+`, поэтому дефисные слова считаются консервативно несколькими. Одна исходная ведущая `Алиса, ` допускает иной регистр и нормализуется; TTS получает каноническое `Алиса, ` ровно один раз. Повторное/неправильное обращение и wake-name внутри body отклоняются. Сохраняются исходные body, emotion и gesture одного segment, history получает только прозвучавший body.

Длинное первое предложение, несколько предложений/segments, незавершённый вопрос, ellipsis, повторная пунктуация, альтернативные question marks и markup дают **`AlicePhraseRejected` до reply/audio event и до первого TTS dispatch**. Ничего не обрезается, поздняя короткая фраза не выбирается, запасной факт не сочиняется. Генерация одна, model retries0; конечный fallback — явный failed turn через существующий worker error path, без replacement speech. Лингвистическую/фактическую истинность синтаксический validator не доказывает. Политика консервативна: например, десятичные точки, сокращения с точкой и выражение, разбитое style tag посреди предложения, также отклоняются.

В Alice-режиме нет canned acknowledgement: accepted turn имеет один `synthesize_wav` или один `tts.synthesize`, хотя Piper и PCM могут иметь несколько chunks. Проверка повторяется непосредственно у TTS, поэтому unchecked длинный segment не исполняется при прямом вызове этих методов. Совместимость с request-scoped JSON constraints сохраняет их существующий capability gate; S0 не включает schema/SDK routes; дополнительная проверка запрещает менять constrained body при нормализации обращения.

**Tradeoff:** exact worker92cf ждёт целый ответ прежнего `brains.answer`, затем проверяет законченный segment до PCM. Native token streaming/overlap не добавлены. Это может увеличить время до первого аудио относительно отдельного content-stream кандидата. Word count не устанавливает акустическую длительность; Piper/STT/голос/модель и их настройки сохранены. Agent/capture_pump/audio lifecycle, native/autonomous session, camera/transport, README и исторический CREATE UNKNOWN не менялись.
