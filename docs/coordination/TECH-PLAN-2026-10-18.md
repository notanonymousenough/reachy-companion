## Первый сохранённый результат

1. После передачи назначить одного аппаратного владельца; он получает свежий статус без изменения пользовательских переключателей и сохраняет точный установленный R50 fallback. Новый hardware scope не наследует старый gate. Выяснить фактический PC voice contract по малому read-only срезу, не заменять producer canonical-копией вслепую.
2. Source-специалист: одно изменение «Тест с Алисой / Обычный» через существующую панель/авторизованный путь. Сохранённый режим имеет явную версию; одна реплика получает один снимок режима, инициативный и обычный вход используют тот же выбор. В обычном режиме нет тестового имени/контекста, в тестовом есть краткий Alice-контекст и prefix. Смена режима не включает MIC/initiative/motion и не восстанавливает старый intent. Не объявлять выбор режима распознаванием личности говорящего.
3. TL интегрирует с актуальным manifest/profile и проверяет выбранные реальные контракты. Нужные проверки: режим до/после restart, обе outgoing payload ветви, конфликт/параллельный STOP не включает захват, запреты ownership/privacy сохранены. Существующие meaningful panel/voice проверки использовать повторно.
4. Единственный аппаратный владелец устанавливает ограниченное изменение и выполняет живую приёмку: реальная панель → обычный голосовой ответ без Alice-prefix; тестовый ответ с обращением; MIC OFF/STOP сохраняют действие. Физическое начало «Алиса» записывается отдельным фактом U06, не выводится из текста/PCM. Оставить полезный результат работающим с последними пользовательскими настройками. Цель 60 минут, предел первого рубежа 90 минут после передачи.

## Независимый следующий прирост

Ограниченная архитектурная задача (до 30 активных минут, первичные источники): текущая основа против Hermes/OpenClaw/готовой разговорной основы. Решение по времени до интегрированной способности, поддержке отмены/локального PC voice и стоимости миграции; без требования миграции. Рекомендация не блокирует переключатель.

Следующий source scope после определения непересекающихся файлов: текущие реальные audio/visual observations со временем/происхождением → компактный state с TTL → bounded decision scheduler. Дорогие задачи выполняются отдельно; устаревшие результаты не запускают действия. Одно активное задание на ресурс, pending состояние заменяется более свежим. Перегрузка наблюдаема, STOP/ручное управление работают независимо. Приёмка — реальная смена сцены/звук вызывает объяснимую реакцию, следующий sensory tick не ждёт завершения речи/модели.

После этого: сохранённое внимание/штатное движение и речь с движением; долговременный локальный episode/fact/persona storage с происхождением и использованием в следующем разговоре; затем spool→S3→VPS→versioned bundle/rollback при доступных credentials. Доставленный локальный путь и подготовленные внешние контракты отмечать отдельно. U06/U08/U09 остаются самостоятельными ограничениями пригодности общения.
