# Архитектурный выбор: ближайший автономный цикл

18.10.2026. Узкое исследование по поручению нового TL; source edits 0, hardware/remote mutations 0. Прочитаны SPRINT/HANDOFF/TECH-PLAN и компактный срез текущих модулей. Установленное состояние — по HANDOFF, самостоятельной аппаратной проверки здесь нет. Оценки времени ниже инженерные, не измеренный benchmark.

## Одно решение

**Оставить R50 владельцем capture/playback/движения и подключить небольшой асинхронный контур состояния и решений к его действующему пути. Переиспользовать отдельные примитивы `autonomous/`, не запускать старый autonomous profile целиком.** Переключатель режимов идёт независимо и первым. Сейчас миграция на Hermes/OpenClaw не сокращает обязательный bridge к реальному микрофону, playback, policy и STOP. Pipecat — лучший резерв именно для будущей замены разговорного конвейера, если измеренная причина укажет на его необходимость; в текущем этапе его не вводить параллельным владельцем звука.

Новое основание для этого выбора — текущий код уже содержит bounded асинхронные примитивы, а главные отсутствующие стыки конкретны: семантический observation с возрастом, доставка свежего контекста в actual PC voice и единый admission действий. Это не возобновление R41/R44/R45, их runners/model profiles/native actors не предлагаются к запуску.

У Hermes есть существенная оговорка для непрерывного компаньона: память обновляется через tools, а session snapshot заморожен; документация прямо связывает пользу recall с границами сессий и предупреждает о ложных «запомнил» у слабых local models. Значит, миграция сама не даёт живого обновления working memory. [Hermes memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).

Все времена кандидатов — оценки с низкой уверенностью, установки/benchmark не выполнялись. Утверждение «готовая основа уже совместима с Reachy» не сделано ни для одного кандидата. У всех остаётся обязательный Robot adapter; полноценная миграция не оценена и не обещается.

## Минимальный интеграционный контракт

1. **Observation → state:** из одного действующего capture owner публиковать compact audio/VAD/activity/classification; из существующего snapshot VLM — ограниченный semantic observation. Каждый элемент: source boot/seq/id, modality, monotonic receipt, известный capture/inference age, TTL, quality/uncertainty, lineage. До доказанной верхней границы свежести — unknown, не инструкция модели и не причина конкретного утверждения о сцене. Один running VLM job, один заменяемый latest request; сырые медиа не накапливать.
2. **State → decision:** короткий local tick (стартовая гипотеза 0.5–1 с) обновляет состояние даже во время TTS/LLM. Дешёвые правила выполняют admission/cooldown/приоритеты; модель получает state delta только при новом событии либо ограниченном idle deadline. Один model decision in flight, один заменяемый snapshot; никакого catch-up burst. Fast policy может выбрать wait/attend/ask/answer/start-work, но не дать себе motor/MIC разрешение. Сначала существующий загруженный PC model; отдельная 0.6B модель — только после измерений latency/quality, не prerequisite.
3. **Decision → proposal → existing executor:** предложение связано с observation ids, decision revision, mic/policy/mode epochs и expiry. Последняя проверка в R50 непосредственно перед исполнением. Речь — через один существующий voice slot; движение — через существующий guarded motion path. Новая речь пользователя вытесняет инициативную реплику; STOP/privacy срабатывают независимо от inference. Старый/отменённый result не воспроизводится, занятый backend не объявляется свободным по timeout.
4. **Memory/persona:** локально сохранить ограниченный episode с evidence и версией; отобранные facts писать в существующий MemoryStore. Перед ответом читать свежий bounded projection и versioned persona. Модель предлагает изменения persona/goal, owner фиксирует версию/основание/rollback; sensor text не меняет permissions/principles. Рубеж — реально использованный факт в следующем разговоре после restart, а не успешный SQLite INSERT.
5. **Позже S3/VPS:** локальный durable spool с id/checksum/schema/version, retry без дублирующих событий; экспорт по allowlist компактных эпизодов и разрешённого контента, без raw media/transcripts по умолчанию. VPS выдаёт candidate memory/persona bundle с parent version/evidence; локальная проверка и атомарное переключение с rollback. Наличие credentials и работающий upload/restore проверить отдельно; этот документ не объявляет внешний конвейер доставленным.

## Приёмка ближайшего прироста и fallback

Сохранённый результат: реальная смена сцены или подтверждённое звуковое событие обновляет state, decision ссылается на это событие и вызывает разрешённую реакцию; пока дорогая обработка/речь занята, другие observations продолжают обновляться. Показать возраст/занятость/dropped или superseded счётчик; не засчитывать случайное шевеление, fixture либо текст, не поступивший с реального сенсора. Затем проверить отмену/устаревание и MIC OFF/STOP. U06/U08/U09 и оставленное движение остаются отдельной приёмкой.

Если за 30 активных минут bridge не даёт локального сквозного observation→decision→proposal, сузить до одного реального сенсора и одного уже существующего действия, а не подключать ещё framework. Если actual PC contract не совместим без замены worker — сначала добавить узкий совместимый adapter, сохранить R50 voice. Откат отключает только новый контур/selector; не восстанавливает старый MIC/intent поверх пользовательского OFF. R50 и все открытые жалобы сохраняются.
