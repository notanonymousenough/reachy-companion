# R19 — следующий срез: реальные native-входы в normal FastView

17 октября 2026, Europe/Moscow. SOURCE-ONLY решение; единственная запись — этот документ.
Код/runtime/PROJECT/baseline не менялись; remote/network/model calls, arm/deploy и новые чаты/подагенты не выполнялись.
Текущие ограничения: S7 — единственный hardware owner; normal voice ON, observer OFF после D3, permanent camera OFF.
PROJECT содержит более старое назначение R18/S6; для этого плана применяется явно переданный актуальный статус S7.

## Решение и evidence

**Приоритет — один normal native perception→FastView срез:** дать fast измеренную динамику существующего audio owner и подключить уже имеющийся camera→PC context path. Сохранить normal Agent единственным владельцем capture/STT/main/reply. Сначала полезные реальные входы, затем проверка естественного выбора; не повторять goal-clock эксперимент.

- [R16](R16-paused-fix-live.md): R15 pair установлена, paused stable/STOP fence PASS, 4 actual wait/4 accepted/0 effects. Исправление churn уже сделано.
- [R17](R17-goal-clock-semantics.md)/[R18](R18-goal-text-live.md): уточнённая operator goal действительно дошла до модели; 2 полных actual wire/tokenizer receipts PASS, 5 actual wait/4 accepted/0 effects. Capability присутствовала; скрытая причина wait UNKNOWN. Новое prompt tuning без новых входов не обосновано.
- [M0](M0-camera-coexist.md)/[M1](M1-camera-live.md)/[A1](A1-continuous-live.md), раздел Camera coexistence: выбран существующий SDK IPC producer; A1 доказала 157 меняющихся кадров рядом с реальным PCM/voice, privacy и STOP. Consumer был на Mac, **PC normal context integration отсутствует**; PTS=0, exposure age upper UNKNOWN.
- [Context](../autonomous-companion/context-live.md)/[perception](../autonomous-companion/perception-live.md): уже есть bounded latest-only PC processing, scope/nonce/revoke и canonical context. UNKNOWN camera имеет пустой summary и не допускается как свежее model evidence. Простое включение камеры не лечит sensor starvation модели.
- Адресно прочитанный source: `CapturePump.Assembler.feed` уже считает RMS/VAD, но native FastView публикует лишь PCM counters/voice phase/elapsed. `NativeState` запрещает второй main/reply; `NativeScheduler` после gap закрывает stock/context до конца session. Эти ограничения сохраняются.

**Почему это повышает шанс осмысленного выбора:** вместо ещё одного clock+UNKNOWN модель сможет видеть реальное изменение измеренного аудиосигнала с provenance и исключением собственного playback. Это проверяемая гипотеза, не обещание settle. Camera часть закрывает конкретный разрыв normal восприятия; до доказанной freshness она даёт только честное состояние канала, без scene claims или visual action basis.

**Idle-controller допустим, но один он недостаточен для выбранного среза.** Дизайн §6 прямо разрешает готовый breathing между решениями; это самостоятельный режим `origin=policy_idle`, с grants/cooldown, тем же единственным executor и вытеснением более приоритетными действиями. Он может отдельно удовлетворять части требования штатного движения при model wait. Он не является model-selected effect proof и не заменяет непрерывные LLM ticks/зрение/слух. Сейчас новый idle writer ещё добавил бы arbitration и expression-version churn до первого доказанного effect; его не вводим параллельно.

**Server authority/motion baseline не объявляем сломанными:** R18 не дошла до proposal. Расширение MOTOR semantics из [R12](R12-motor-authority-boundary.md) принято только для отдельного clock profile; переносить его на audio-derived action или снимать R5 gap closure нельзя. Отдельный явный технический stock baseline допустим позже при конкретном effect blocker, с маркировкой operator/test; ручное действие не засчитывается в autonomy.

## Три следующих малых контракта, последовательно

### 1. Source: один bounded acoustic summary от существующего reader до native FastView

**Файлы/resources:** exact installed A1 pump + R15 Agent preimages; `capture_pump.py`, узкий read-only status export в `agent.py`, normal `NativeAgent/NativeState` в `autonomous/native_agent.py`; целевые `test_capture_pump.py`/native tests. Не менять worker/S7 generation/validator, goal-clock/system prompt/schema и motion guards.
**Изменение:** переиспользовать уже вычисленные RMS/VAD: один latest summary окна ≤1s, уровень/дельта/onset без направления/музыки/identity. Binding: Agent boot, control epochs, source generation, sequence, окно monotonic read receipts, suppression/mask state. Никаких PCM/transcript/image exports, нового recorder, HTTP/callback из reader или второго STT. Privacy/STOP/retire чистят summary; после own-output mask требуется новое чистое окно.
**Acceptance:** exact source→status→NativeState→actual request construction сохраняет measured значения/IDs/clock provenance; stale/ABA/gap/masked/late samples не получают пригодного invitation. Возраст относится к read receipt, не экспозиции/физическому acoustic capture; если нельзя обосновать пригодность окна для реакции — UNKNOWN и POST0, без выдуманного fresh label. Синтетические tests доказывают plumbing, не слух.
**Owner/conflict:** source-only исполнитель; заморозить preimages до edits, Agent/pump менять одним владельцем. S7 владеет стендом; её manifest не подменять checkout. Live в этом контракте нет.
**Exit:** переносимый минимальный patch/manifest/rollback и адресные source checks либо один точный provenance/export blocker; без model calls и prompt-tuning цикла.

### 2. Source: camera→существующий PC ContextProvider→normal native session

**Файлы/resources:** `deploy/autonomous/video_server.py` exact M0 candidate `6182a651…` + установленный SDK1.11.0; существующие `autonomous/context.py`, `video_adapter.py`, `perception.py`; только необходимые normal profile/session/config bindings в `native_agent.py`/`native_agent_session.py` и отдельный public config. Общий native файл — лишь после передачи от №1.
**Изменение:** явно связать один factory IPC reader с PC latest-only processor и background `/context`; не использовать legacy spoken snapshot, который retire-ит слух. PC-owned SQLite остаётся единственным memory owner; без fixture facts, нового store, memory writes или VLM. Existing camera context path расширять только в установленном месте несовпадения, без второго transport/framework.
**Acceptance:** camera summary остаётся пустым при unknown upper age; IDs/lineage/age bounds не превращаются в scene evidence. Privacy/revoke/nonce/owner/source fences, raw RAM bounds и реальная занятость Future сохраняются. Проверить actual projection новой audio summary и camera UNKNOWN вместе, token admission caps не менять. Stock после первого gap по-прежнему закрыт; context не rearm автоматически.
**Owner/conflict:** source-only, без стенда; producer и PC adapter поставляются совместно exact manifest. Не редактировать S7 worker, R15 pair повторно или D0 service admission: service сейчас намеренно запрещает camera/context/stock.
**Exit/liveproof:** reviewable frozen candidate и targeted revoke/late-result/construction checks; hardware claims отсутствуют. Если нужен semantic VLM или новый authority protocol — закончить конкретным blocker, не включать их в этот scope.

### 3. Один joined live window после S7 handoff; без дополнительного clock trial

**Владелец/resources:** один назначенный оператор Robot/Hub/PC после явного S7 handoff и её speech acceptance. Fresh deployed hashes/config/imports/boots/control/owners/known-idle сверить с объединённым manifest №1–2; exact PC fast/9B/Whisper/Piper и existing-auth route, без новых keys/trust/firewall. При несовпадении — STOP до запуска, не «проверка checkout».
**Окно:** один normal finite run ≤120s существующим native entrypoint, period3/deadline6 как измеренный старт; camera/context отдельно opt-in. Один короткий seed «Алиса, …»; после его известного manual retirement начать новый normal measurement scope только на свежем стабильном PCM generation, не переобозначать старые results. Не менять старый audio-only Alice gate.
**Sensory proof:** ≥10 actual accepted fast IDs без необходимости новой реплики, actual wire capture новых acoustic fields и camera UNKNOWN в прежнем cap≤16KiB/≤4 полных requests, реальные frame/processing IDs на PC и продвижение PCM при normal main/TTS; ≥2 fast completions при реальном running main, если интервал достаточно длинный. Слишком короткий main не заменять fixture. Raw media/transcripts не сохранять; exact tokenizer usage связать с request IDs.
**Model-effect proof отдельно:** только явный fresh R5 sensor-stock grant, максимум один прежний settle roll1°→neutral/.5s+.5s, если штатная модель сама выберет его. Это изменённые реальные inputs, не повтор R17. При любом gap прежняя physical/context closure; без motor-only fallback/rearm. `wait` допустим и не переписывается. PASS эффекта требует request→choice→accepted binding→proposal→≤1 effect attempt→оба server guards→независимую pose telemetry; HTTP/idle-controller/ручной baseline не зачёт.
**Exit:** честные отдельные verdicts joined perception / model selection / physical effect. Если все choices wait — input-срез может пройти, motion proof остаётся FAIL/UNKNOWN; никаких второго arm, forcing, нового prompt или бесконечного окна. Если пригодного acoustic evidence не было — проверить №1, не запускать новый clock trial. Effect UNKNOWN → HOLD/reconciliation без POST retry.
**Cleanup:** STOP/privacy probe с late-output check, current guarded motorOFF, revoke/NULL/reap собственных camera/context/session/bridge и known-idle receipts; normal listening ON только отдельным свежим штатным control шагом. D3 observer не возобновлять автоматически. Постоянная camera/service этим finite proof ещё не принята; PROJECT/baseline меняет root по фактическому handoff.

## Неизменные границы и полный дальнейший target

Во всех трёх контрактах: один physical writer; STOP/privacy/quiet/boot/epoch/owner/error и real expression-version fences; исходные model/goal deadlines, BEGIN/effect <300ms и server CAS каждого target; single-use reservations до dispatch, no POST retry/no replay; занятый или UNKNOWN slot не освобождается timeout/cancel. Нельзя удалять guards ради camera/service или объявлять manual action автономным.

После этого среза остаются обязательными по [дизайну §§1,6,14–17](design-2026-10-17.md) и [DELIVERY-PLAN](DELIVERY-PLAN.md): policy breathing в общем motion owner и полный штатный repertoire; отдельно model-selected physical effect; integrated camera/audio/motion/voice; исправленный D3 terminal lifecycle и явный combined service admission, ≥30min interval и оставленная активной служба без finite cap, controlled restart/reconcile и дальнейшие часы эксплуатации. Это следующие изменения существующего пути, не разрешение снять service guards сейчас.
Streaming overlap/AEC/barge-in и acoustic краткость, semantic scene/audio/music→look/dance, attention/task continuation/overload barrier, persistent goals/progress, voice→provenance memory→next-main между сессиями, episodes/facts/procedures/conflict/forget, обратимое развитие личности/принципов, durable bounded spool→S3 immutable batches→VPS consolidation→versioned atomic bundles/rollback, дополнительные sensors/tools и измеренная resource optimisation сохраняются полностью. Camera exposure freshness остаётся отдельным доказательством до любых visual actions; первый полезный runtime не выдаётся за весь дизайн.
