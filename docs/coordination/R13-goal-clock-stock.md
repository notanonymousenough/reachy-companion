## Semantic change и граница

Это явная policy корректировка [R12](R12-motor-authority-boundary.md), а не доказательство continuous PCM. Новый профиль `native_agent.stock_profile=finite_goal_clock` допускает ровно **один initial settle** по статической operator goal и clock при действующем motor grant. `listening/capture_active/phase/source_generation` не создают motor permission. Изначальный durable Mic OFF допустим; его enabled/epoch/owner всё равно закреплены как консервативный STOP fence. `error/stopped` остаются known terminal control failure/STOP evidence.

`motor_identity()` валидирует полный typed operator через неизменённый `control_authority()` и закрепляет Agent boot, mic epoch/enabled/owner, policy epoch/motor/quiet/privacy/owner. Начальные owners обязаны быть null. Quiet/privacy/моторный запрет, boot/epoch/owner change, malformed authority, ошибки persistence/exhausted epochs и effect UNKNOWN терминальны для arm. Новый GET или прежние значения после ABA этот arm не оживляют. Цель закреплена целиком, включая id/version; её изменение закрывает arm. TTL 1..180s превращается в monotonic expiry при явном arm, не продлевается.

Отдельный `read_motor_receipt()` получает настоящие Hub `/status` и `/control/operator`, фиксирует `begin_monotonic` (`received` — тот же BEGIN для совместимости с scheduler), Hub boot и typed operator/expression version. Admission требует stock selected/known/unowned, Hub free/idle, ready daemon и enabled motors, current motor policy, прежние identity и boots. `capture_pcm` не участвует в grant. BEGIN-age остаётся строго <300ms. Timeout закрывает admission до нового полного receipt; уже замеченный known revoke публикуется до следующего read. Effect preflight не продлевает original proposal deadline.

Sensor/control polling использует один прежний actual `poll_job`; чтение sensor, даже зависшее, не обходится вторым polling Future. Известный audio gap/retirement/replacement/counter regression немедленно увеличивает decision generation и инвалидирует старые решения; занятый fast Future остаётся занятым до actual completion, без replacement/catch-up. Ни initial receipt, ни replacement не объявляются continuous PCM: отчёт всегда `sensor_state=UNKNOWN`, `pcm_continuity=false`. Новый clock/goal request после gap разрешён лишь при свежем motor receipt и прежнем arm. R5 `physical_closed_after_gap` сохраняется как legacy diagnostic, но в этом отдельном профиле не запрещает новый независимый clock/goal proposal.

FastView содержит goal/version, clock/elapsed/remaining TTL, durable operator fields и разрешённую capability; audio/PCM/voice/transcript/context/camera/previous model rationale отсутствуют. Input/content events отвергаются. `basis=operator_goal_clock` задаёт trusted state adapter; модель не может передать `basis` через FastChoice. Binding закрепляет request/session/control identity, Hub boot, decision generation, goal id/version и model deadline. Proposal фиксирует один receipt/operator/expression fence; конкурентный poll не может перебиндить старый fast result на новый generation.

Deadline единожды вычисляется как `min(model_binding.deadline, receipt_BEGIN + .3, goal_expiry)`. После reservation существующий executor отправляет только roll 1°→neutral, `.5s/.5s`, `minjerk`, нулевые остальные координаты и antennas. Preconnect, свежий typed operator/identity/expression reread и локальный nonblocking predicate перед каждым header/body/partial socket send сохранены. Полное сравнение observation fields заменено только в новом профиле на motor projection + expression fence. Неизменённые Hub `expression`/`stock_check`/`robot` проверяют server guards перед каждым из двух targets.

`stock_used` резервируется до Job и никогда не сбрасывается, в том числе при pre-send отказе. Любой attempted/partial send/lost response остаётся одной попыткой/UNKNOWN без POST retry. Пока reserved effect действительно занят, polling busy не выдаёт новый motor receipt: admission HOLD до результата/reconciliation. Effect preflight при busy всё равно POST0; unknown/foreign ownership и ошибки не превращаются в free. После completion slot остаётся использованным.

## Durable disable audit и ограничения

По unchanged exact R8 и [R4](R4-authority-epoch-contract.md): control `/microphone`, spoken STOP/pause, response STOP и pump/barge STOP идут через `set_microphone(False)` с epoch increment и persisted save/fsync; `/motion-policy` через `set_motion_policy`→`MotionPolicy.save` с CAS, epoch increment, file/directory fsync. Privacy/quiet/denial сохраняются до speaker/expressions hold. Same-value/owner round-trip увеличивает epoch. Ошибка сохранения/неизвестный epoch закрывает authority, а не подтверждает durable OFF. Temporary `/pause`/manual retirement не считаются full STOP.

Native `/stop`, signal и явный operator event закрывают local arm; Event проверяется непосредственно в send predicate, до ожидания scheduler loop. **Event не является durable motor OFF receipt.** Процесс не включает policy, не восстанавливает persisted ON и не делает auto-rearm/restart. До нового arm D2 должен завершить/reconcile slots и подтвердить durable disable штатным guarded policy/microphone путём. Если save/reap/ownership не подтверждены — HOLD, без повторного запуска, epoch rollback или очистки UNKNOWN.

Static operator goal и её происхождение — trusted input; код исключает sensor payload из FastView, но не доказывает смысл текста, вручную введённого оператором. Наличие <=300ms окна на реальном транспорте здесь не измерено; extra status/operator reads могут честно закрыть admission по timeout. Никакой обязательной атомарности всех sensor reads не добавлено. Нет proof произвольного LAN/power loss/file rollback/второго writer и нет hard-stop/pose certification. R11 retirement epoch, если его отдельно установят, консервативно отзовёт этот mic-pinned arm; автоматически принимать новый epoch запрещено.
