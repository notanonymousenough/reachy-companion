## Минимальная правка

Один новый patch [alice-format-voice.py.patch](../../deploy/patches/alice-format-voice.py.patch) поверх **S0 voice output**, builder [prepare_alice_format.py](../../deploy/autonomous/prepare_alice_format.py), tests [test_alice_format.py](../../tests/test_alice_format.py). Frozen S0 builder/patches/tests/docs, HEAD `src/reachy_companion/{voice,config}.py` и runtime/config не изменены. Agent/audio lifecycle/normal session/camera/transport/model/backend/voice weights не затрагиваются; новых зависимостей нет.

В exact `Pipeline.answer` прежний system prompt получал историю и user input, но не Alice phrase constraints. Штатный репозиторный prompt допускает 1–2 предложения и несколько expression fragments; это не согласовано с S0 single-segment gate. S2 добавляет в конец **первого system message перед единственной `brains.answer`** явное request-local правило, заменяющее прежние правила краткости/формата: одно законченное предложение, один ведущий `Алиса, `, ≤11 слов/120 символов вместе с обращением, ≤10 слов body, конечный `.`, `?` или `!`, без хвоста/обрыва/Markdown/newline/ellipsis; необязательные emotion/gesture tags только в начале. Effective private prompt не читается и не переписывается; его persona сохраняется в этом же message. Изменение не опирается на max_tokens или новую persona и не меняет model selectors/settings.

Инструкция передаётся только при совместных `conversation.alice_short_replies=true` и effective request prefix=`Алиса, `. Request override `speech_address_prefix=""`, config prefix="", absent/default-false flag сохраняют прежние model arguments, полный ответ, TTS/events и history. В следующий human request Alice format не протекает, config остаётся прежним. `/say` не генерирует ответ: к нему применяются только проверки фразы. Существующий capability gate для `reply_constraints` и требование неизменного constrained body сохранены; schema route не включается.

Если модель всё же выдаст несколько разрешённых style segments **одного** короткого законченного предложения, `alice_short_segments` соединяет **все** texts пробелами в исходном порядке. Сохраняется начальная emotion/gesture для единственного segment; поздние изменения стиля не исполняются. В `prepare` дополнительно сравниваются последовательности слов исходного текста после удаления только известных expression tags и полного aggregate: метка внутри слова/создание новой границы слова отклоняется. Действующий parser с cap 8 segments сохраняет хвост в восьмом; test доказывает его присутствие при aggregate validation.

Затем **тот же byte-identical S0 `validate_alice_phrase`** проверяет весь aggregate: одно законченное предложение, ≤11 слов включая prefix, ≤120 символов, нормализация одного ведущего обращения, отсутствие duplicate/malformed/wake prefix в body и прежние punctuation/markup запреты. Проверка повторяется у TTS boundary. Первый кусок/короткий хвост не выбирается, слова не заменяются/не отбрасываются, вопрос не режется. Multi-sentence, 12+ слов, незавершённый текст и duplicate prefix остаются `AlicePhraseRejected` до reply/audio event и первого TTS. Acknowledgement по S0 отключён. Одна генерация, model retries0, second LLM rewrite loop отсутствует; failed turn без replacement speech. Accepted unary/stream turn имеет один TTS dispatch, независимо от числа Piper/PCM chunks; history получает только полный озвученный body.
