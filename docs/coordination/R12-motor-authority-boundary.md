# R12 — граница MOTOR authority и audio lineage

17 октября 2026, Europe/Moscow. **READ-ONLY source/design review; единственная запись — этот документ.** Устройства/HTTP/SSH/models, source edits, чаты/подагенты не использовались. R8 установлен по R9; R11 source-ready, не установлен. Аппаратная работа D1 ограничена observation service. Этот review не разрешает implementation, motor arm, installation или live.

## Решение и основание

**Временные audio pause/manual/source retirement не обязаны терминально отзывать MOTOR authority.** Same PCM `source_generation` → stock admission — консервативное ограничение нынешнего bridge, не общее пользовательское требование. [Дизайн §1](design-2026-10-17.md#1-цели-и-инварианты) прямо допускает решения по времени/другим входам при Mic OFF; §§4–5 задают clock/goal inputs и проверку существенных именно для действия предусловий. §15 требует текущие grants, STOP/privacy и UNKNOWN discipline. Always ON требует постоянного цикла и допустимых движений, но не непрерывного движения.

[R4](R4-authority-epoch-contract.md) доказывает durable microphone/policy/owner ABA через штатные mutators, отдельно исключая listening continuity. [R7](R7-stock-rearm.md) и [R10](R10-stock-rearm.md) опровергают вывод «составной fresh receipt доказывает живой прежний PCM source». Они не доказывают отзыв motor permission при manual. [R11](R11-retirement-authority.md) корректно усиливает выбранный retirement fence, но источник обязательности такого MOTOR-смысла в дизайне отсутствует. Для сохранения **нынешней** terminal-audio policy R10 gap остаётся: нельзя снять только `physical_closed_after_gap`; R11 закрывает конкретный контрпример, не даёт общего rearm acceptance. [R5](R5-observer-recovery.md) и текущие [native guards](../../src/reachy_companion/autonomous/native_agent.py), [Hub](../../src/reachy_companion/hub.py), [MotionPolicy](../../src/reachy_companion/motion_policy.py) задают сохраняемые проверки; checkout не является deployed attestation.

## Один рекомендуемый минимальный контракт

Первый scope — **один finite initial stock `settle` по явной operator goal и clock**, независимо от наличия PCM. Никакой реакции на звук/транскрипт/старый voice phase. Новые control epochs/framework не нужны.

1. В `native_agent.py` выделить `motor_identity(operator)` из полного typed operator: `agent_boot_id`, `microphone_epoch/enabled/owner_id`, `motion_policy.epoch/motor_enabled/quiet/privacy_all`, `motion_policy_owner_id`. Mic fields временно оставить дополнительным консервативным durable STOP/owner fence; mic enabled может быть false при исходном arm. Не включать `listening/capture_active/phase/source_generation`. `expression_version` сравнивать отдельно как action fence. `control_authority()`/shared client и Hub guards не ослаблять.
2. `read_motor_receipt()` получает **свежие** Hub `/status` и `/control/operator`, хранит `begin_monotonic`, motor identity, expression version, Hub boot. Весь effect-read ≤300ms от BEGIN; проверяет typed policy, отсутствие state error, motor=true, quiet/privacy=false, согласованные boots, owners соответствуют arm (первоначально оба null), stock selected/known/unowned, Hub free/idle. `/status.capture_pcm` никогда не источник motor grant. Timeout закрывает admission до нового полного receipt; malformed authority/error/known withdrawal — terminal. Последующий timeout не скрывает уже прочитанный revoke.
3. `motor_grant` — существующий явный finite `allow_stock` arm, привязанный к session/boots/server identity, `goal_version`, одному settle и unused slot. Trusted operator goal получает version/expiry при arm; изменение goal инвалидирует binding. Goal, model result и успешный GET сами arm не создают. Новые epochs/owner требуют нового явного arm после cleanup; их нельзя автоматически принять вместо отозванных. Отсутствие свежего receipt означает UNKNOWN authority, а не разрешение по кэшу.
4. В `NativeState.snapshot/bind/apply` и `NativeScheduler.advance` отделить motor freshness от PCM freshness. Для этого scope FastView содержит operator goal/version, clock/elapsed, current разрешённую capability; PCM/voice payload исключён, sensor availability честно UNKNOWN. `basis=operator_goal_clock` назначает trusted adapter, не модель. Binding: `request_id`, session/control identity, `decision_generation`, goal version, deadline. Proposal добавляет receipt BEGIN/expression version. Разрешён только фиксированный существующий settle: roll1°→neutral, два шага по0,5s; цель не расширяет профиль.
5. `dispatch/admit_stock/execute_stock/guarded_control` сохраняют reservation **до** Job, один owner/slot, отсутствие replay. Deadline = min(model binding deadline, motor receipt BEGIN+300ms, goal expiry); reread не продлевает его. После preconnect — свежий typed operator reread, прежняя durable identity и expression fence; сравнение observation fields заменить motor projection. Перед каждым header/body/partial socket send — локальный nonblocking admission и deadline. Hub `expression/stock_check/robot` сохраняют собственные fresh server checks непосредственно перед каждым эффектом; native receipt их не заменяет. Sent/partial/lost response — UNKNOWN, slot used, reconciliation; no POST retry.

## Terminal, sensor UNKNOWN и старые решения

STOP, privacy, quiet, explicit autonomy disable, motor=false, boot/control epoch/owner change, exhaustion/persistence error, unresolved effect/ownership UNKNOWN сохраняют terminal closure текущего arm. Для STOP/disable должен оставаться durable server путь: существующий microphone STOP fence и/или guarded `set_motion_policy`→`MotionPolicy.save(motor_enabled=false)` с CAS/fsync. Локальный `/stop` немедленно закрывает admission; один Event не доказывает durable disable. До enable проверить все disable callers; при неподтверждённом сохранении — HOLD, без restart/rearm. Старое persisted ON/epochs не восстанавливать.

PCM timeout/expiry, pause/manual retirement, смена source/counter regression означают UNKNOWN/discontinuous **sensor**, не моторный отзыв. Любой замеченный разрыв увеличивает `decision_generation`, удаляет pending proposal, инвалидирует старый fast result; занятые Futures/permits сохраняются до завершения, без replacement/catch-up. Для motor/sensor polling сохраняется один actual poll slot: зависший sensor read нельзя обходить вторым Future. Audio-derived proposals отклоняются в этом scope всегда. Новый clock/goal request после разрыва может действовать только с current motor grant и свежим effect receipt. На R11 mic epoch при retirement всё ещё закроет этот минимальный arm консервативно; избавляться от mic fence сейчас не предлагается.

## Проверки, риск и следующий scope

Нужны deterministic offline tests: R10 composite trace при audio UNKNOWN допускает только **новое** clock/goal settle, старый result/proposal POST0; pause/manual/source replacement не выдаются за PCM continuity; STOP/OFF→ON, privacy/quiet/owner ABA и disable отвергают прежний arm; expired/malformed receipts, foreign owner, busy/UNKNOWN дают POST0; revoke на socket barrier даёт POST0, partial/lost response — ровно один attempt/UNKNOWN/no replay; каждый из двух Hub steps сохраняет server guards.

Основной риск — скрытая зависимость model context от аудио либо путаница pause с full STOP. Ограниченный FastView и durable disable tests обязательны. Это не proof произвольного LAN/hardware failure и не hard-stop certification.

**Следующий небольшой scope:** отдельный offline native-only candidate в двух native modules и целевых tests для указанного finite clock/goal settle; без Agent/Hub/R11 установки и без service-stock enable. D1 observation-only не менять. До отдельного review/live handoff действующий R5 physical closure сохраняется. Rollback будущего candidate: закрыть admission, завершить/сверить занятые slots, UNKNOWN не очищать; вернуть exact native preimages и R5 closure, без rollback persisted control epochs.
